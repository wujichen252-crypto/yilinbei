## 1. 【关键】模板结构：数据必须从第 3 行开始

官方模板 = `yl-frontend/public/static/参演人员导入模板.xlsx`（与 `dist/static/` 下同名文件 md5 一致），逐格内容：

| | A | B | C | D | E | F | G | H | I | J | K |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| **第1行** | `index` | `name` | `card` | `gender` | `age` | `school` | `phone` | `type` | `position` | `instrument` | 所有信息都必填,且请勿删除头部信息,否则可能导入失败 |
| **第2行** | 序号 | 姓名 | 身份证 | 性别 | 年龄 | 所在学校名称 | 联系电话 | 身份 | 角色 | 使用乐器 | （空） |
| **第3行起** | 1 | … | … | … | … | … | … | … | … | … | |

工作表名：**`用户表`**。本测试集每个文件的前两行都与官方模板**逐格一致**（`06_header_error.xlsx` 除外，它就是拿来破坏表头的）。

### 这解释了 `i = 1` 的循环起点——它不是缺陷

```js
const sheet = res.map(i => i.sheet).find(s => s && s.length > 1)   // 第一张有数据的表
for (let i = 1; i < sheet.length; i++) { ... exportCheck(sheet[i]) }
```

`sheet` 的下标 0 **就是那张中文标签行**，从 `i = 1` 开始正是为了跳过它。数据行 = 下标 1 起 = **Excel 第 3 行起**。

> v2 的说明书曾把这里写成「首位成员被静默丢弃的缺陷」——**那个结论是错的**，它其实是因为 v2 的测试文件缺了标签行、数据从第 2 行开始，才让第一条成员顶到了被跳过的位置。官方模板下不会丢人。

**报错行号**：提示的 `第N行` 中的 N 就是 `sheet` 下标，对应 **Excel 第 N + 2 行**。

## 3. 字段与规则

### 3.1 列

| 表头 | 含义 | 前端必填 | 值格式 |
| --- | --- | --- | --- |
| `index` | 序号 | 否（不校验） | 任意 |
| `name` | 姓名 | **是** | 非空；**无数字**；**长度 2–20** |
| `card` | 身份证 | **是** | **`^\d{17}[\dXx]$`**（18 位，末位数字或 X） |
| `gender` | 性别 | **是** | **只能 `男` / `女`** |
| `age` | 年龄 | **是** | **整数（`^-?\d+$`）且 5 ≤ age ≤ 80** |
| `school` | 所在学校名称 | **是** | 非空；**不能是纯数字** |
| `phone` | 联系电话 | **是** | **`^1[3-9]\d{9}$`**（11 位手机号） |
| `type` | 身份 | **是** | **只能 `学生` / `教师`** |
| `position` | 角色 | **是** | **只能 `正式队员` / `预备队员` / `指挥`** |
| `instrument` | 使用乐器 | **是** | 非空（**不校验枚举**） |

列顺序无关（按表头文本匹配），但**十列必须齐全**。第 11 列的提示语可随意，用不到。

> `major`、`number` 在官方模板里**不存在**。
> `PersonTableMajor.vue`（需要 `major`、且允许 `伴奏`）**没有被任何组件引用**，是死代码。

### 3.2 五条格式规则（`src/config/personFields.js`）

这是 v3→v4 的关键补充，来源是你实测的两条报错文案反查到的模块：

```js
const RE_CARD = /^\d{17}[\dXx]$/        // 身份证号应为18位，末位可以是数字或X
const RE_PHONE = /^1[3-9]\d{9}$/        // 联系电话应为11位手机号
const RE_INT = /^-?\d+$/                // 年龄必须是整数
const RE_HAS_NON_DIGIT = /\D/           // 学校名称不能是纯数字
const AGE_MIN = 5, AGE_MAX = 80, NAME_MIN = 2, NAME_MAX = 20

checkPersonName    : trim → 空则跳过；含数字 → '姓名不能包含数字'；长度不在 2–20 → '姓名长度应为2-20个字符'
checkPersonCard    : trim → 空则跳过；不匹配 RE_CARD → '身份证号应为18位，末位可以是数字或X'
checkPersonAge     : trim → 空则跳过；非整数 → '年龄必须是整数'；越界 → '年龄应在5-80之间'
checkPersonSchool  : trim → 空则跳过；纯数字 → '学校名称不能是纯数字'
checkPersonPhone   : trim → 空则跳过；不匹配 RE_PHONE → '联系电话应为11位手机号'

checkPersonBasics(item) = 按 name → card → age → school → phone 顺序取**第一个非 null 的报错**
```

两个容易踩的点：

1. **每条都先 `trim`，空值一律返回 `null`（不算格式错误）**。所以纯空格的 `name` 不会被 `checkPersonName` 拦下，它的「必填」拦截靠的是 `exportCheck` 里那句 `if (!item.name)`——而 JS 里 `"   "` 是**真值**，所以纯空格名会被整体放行（见 §9 行为记录 #4）。
2. **`checkPersonCard` 只验格式，不验校验位、不验行政区划代码**。`000000000000000000`（18 个 0）能通过。

### 3.3 完整校验顺序

`personFields.js` 的注释只说「调用方把它插到自己原有的判定顺序里即可」，而本地前端落后远端 44 个提交、且 `git fetch` 被连接重置，**拿不到你正在跑的那一版**。因此下面第 3 条的位置是**推定**的：

```text
1  !name                        → 姓名不能为空
2  !card                        → 身份证不能为空
────────── 以下五条来自 checkPersonBasics，位置为推定 ──────────
3  name 含数字                   → 姓名不能包含数字
4  name 长度不在 2–20            → 姓名长度应为2-20个字符
5  card 不匹配 ^\d{17}[\dXx]$    → 身份证号应为18位，末位可以是数字或X
6  age 非整数                    → 年龄必须是整数
7  age 不在 5–80                 → 年龄应在5-80之间
8  school 是纯数字               → 学校名称不能是纯数字
9  phone 不匹配 ^1[3-9]\d{9}$    → 联系电话应为11位手机号
──────────────────────────────────────────────────────────
10 !age                         → 年龄不能为空
11 gender 空                     → 性别需填写
12 gender 非 男/女                → 性别格式只能是男、女
13 !school                      → 学校名称不能为空
14 !phone                       → 电话号码不能为空
15 type 空                       → 身份不能为空
16 type 非 学生/教师               → 身份格式只能是学生、教师
17 position 空                    → 角色不能为空
18 instrument 空                  → 使用乐器需选择
19 position 非 正式/预备/指挥       → 角色格式只能是正式队员、预备队员、指挥
```

> **第 3–9 条的位置未经代码确认**（理由同上）。
> **影响范围仅限 `07_boundary.xlsx` 的首错行**：若这组判定被放在第 10 条之后，`07` 的首错会从 `第27行姓名长度…` 移到最后一条更早的必填失败上。`05` / `09` 的首错行与全部「通过」文件**不受影响**——它们要么只错一处，要么在 basics 之前就已经有必填失败。要精确定位，把 `07_boundary.xlsx` 第 27–65 行**按行拆成单文件**逐条试即可。

**任一行失败即整批中止**（`return`），所以每个含错文件**只能观察到一条**错误信息，且是遍历顺序中第一条失败行。

## 4. 两层校验的分工

| 层 | 位置 | 检查内容 |
| --- | --- | --- |
| 前端（权威） | `PersonTable.vue:exportCheck` + `config/personFields.js` | 上述 19 条 |
| 后端 | `apps/core/services.py:store_people` | **只有 `name` + `card` 非空**、`card` 全局唯一、全批事务 |

前端放行、后端拒绝（或反之）的值：

| 值 | 前端 | 后端 | 结果 |
| --- | --- | --- | --- |
| `name = "   "`（纯空格） | **通过**（`!item.name` 对 `"   "` 为假，且 `checkPersonName` trim 后返回 null） | `"   "` 在 Python 里也是真值 → **通过** | ⚠️ **空白姓名真的会入库** |
| `name = ""`（真空） | 拒绝（第 1 条） | 拒绝 | 整批失败 |
| `card = "000000000000000000"` | 通过（只验格式） | 通过（非空） | 18 个 0 的身份证可入库 |
| `age = "abc"` | 拒绝（第 6 条，v4 新增） | `IntegerField` 转换报错 | 前端就拦住了 |
| `school` 256 字符 | 通过（无长度校验） | 数据库 `varchar(255)` | 取决于数据库 |
| `instrument = 123`（数字） | 通过（只判空） | 不校验 | 数字型乐器名可入库 |

后端完全不看 `age/gender/school/phone/instrument/type/position`。

## 8. 数据安全声明

- **姓名、学校全部虚构**，由确定性姓名字池生成；学校名取自公开中学名，不指向任何具体个人。
- **身份证 = 6 位地区码 + 8 位出生日期 + 3 位顺序号 + 1 位国标校验位 = 18 位**。
  地区码一律以 **`00`** 开头（我国行政区划代码**没有 00 段**），校验位按 GB 11643 算出。
  → **格式合法、校验位正确，但结构上不可能对应任何真实个人。**
  示例：`000010200001010016`、`00001020000210038X`。
- **电话 = `14` + `0~4` + 8 位 = 11 位**，形如 `14100000001`。
  `140`–`144` 段**未分配给公众移动通信**（`145`/`146` 是联通、`147`/`148` 是移动、`149` 是电信），
  → 满足 `^1[3-9]\d{9}$`（`4 ∈ [3-9]`），**但不是一个真实可用的号段**。
- **未从任何数据库导出或复制真实信息**；不使用生产库生成测试数据。
- 全部测试记录的 `card` 均以 `0000` 开头，与正式数据天然隔离，可一次性定位清理：
  ```python
  Person.objects.filter(card__startswith="0000").delete()   # 切勿无过滤 delete()
  ```
