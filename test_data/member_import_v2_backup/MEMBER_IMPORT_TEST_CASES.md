## 0. 上一版为什么报「参演人员名单第1行姓名不能为空」

上一版用了中文表头（`姓名`/`身份证`/…）。**这是错的。**

真实导入在前端完成，解析用 `XLSX.utils.sheet_to_json()` 的**默认模式**——
它把**第一行单元格文本直接当作对象的键**。所以表头必须是**英文字段名**：

```text
中文表头 "姓名"  ->  行的键是 "姓名"，代码读的却是 row.name  ->  undefined
                  ->  exportCheck 第一句 !item.name 成立
                  ->  ElMessage.error('导入失败！参演人员名单第1行姓名不能为空')
```

这正是你看到的报错。（报错文案是 `参演人员名单`，不是 `参展人员名单`。）

## 2. Excel 模板（必须照此格式）

**第 1 行 = 表头，单元格文本必须是下列英文字段名。** 列顺序任意（按文本匹配），但**每一项都必须存在**。

| Excel 表头 | 含义 | 前端必填 | 值格式 | 后端 `Person` 字段 |
| --- | --- | --- | --- | --- |
| `name` | 姓名 | **是** | 任意非空文本 | `name` |
| `card` | 身份证 | **是** | 任意非空文本（**无格式校验**） | `card`（全局唯一） |
| `gender` | 性别 | **是** | **只能 `男` / `女`** | `gender` |
| `age` | 年龄 | **是** | 数字或非空文本；**`0` 会被判为空** | `age` |
| `school` | 学校名称 | **是** | 任意非空文本 | `school` |
| `major` | 专业名称 | 否（仅 Major 变体要求） | 任意文本 | `major` |
| `phone` | 联系电话 | **是** | 任意非空文本（**无格式校验**） | `phone` |
| `instrument` | 使用乐器 | **是** | 任意非空文本（**不校验枚举**） | `instrument` |
| `type` | 身份 | **是** | **只能 `学生` / `教师`** | → `ReportPerson.type`（学生=0，教师=1） |
| `position` | 角色 | **是** | **只能 `正式队员` / `预备队员` / `指挥`** | → `ReportPerson.position`（0/1/2） |
| `number` | 编号 | 否 | 任意文本 | **后端无此字段，被丢弃** |

### 2.1 值必须是中文枚举

`gender` / `type` / `position` 在 `exportCheck` 里是**与中文字符串精确比对**的：

```text
gender    ∈ {"男", "女"}
type      ∈ {"学生", "教师"}
position  ∈ {"正式队员", "预备队员", "指挥"}
```

写成 `male` / `0` / `1` 一律报「格式只能是…」。

`instrument` **只判非空**，不比对枚举——填「萨克斯风」也会通过。
但界面下拉的合法值是 17 项：短笛、长笛、单簧管、低音单簧管、中音萨克斯、次中音萨克斯、上低音萨克斯、双簧管、大管、小号、长号、圆号、上低音号、大号、打击乐、低音大提琴、其他。

### 2.2 单元格类型陷阱

| 陷阱 | 后果 |
| --- | --- |
| `card` 存为**数字**（18 位身份证） | sheet_to_json 按 JS 双精度浮点读取 → **精度丢失**，末位被改写 |
| `=1+1` 之类的值 | Excel 视为**公式**；无缓存值时 sheet_to_json 读回 **null** → 报「姓名不能为空」 |
| `age` 存为 `0` | `!item.age` 为真 → 报「**年龄不能为空**」（合法值被误拒） |

本测试集把身份证一律写成**文本**单元格；`07_boundary.xlsx` 中另有专门用例暴露上述行为。

## 3. 前端校验规则（`exportCheck`，顺序即报错优先级）

```text
1  !name                        -> 姓名不能为空
2  !card                        -> 身份证不能为空
3  !age                         -> 年龄不能为空        (注意：age=0 也会命中)
4  gender 为 undefined/""        -> 性别需填写
5  gender 不是 男/女              -> 性别格式只能是男、女
6  !school                      -> 学校名称不能为空
7  !phone                       -> 电话号码不能为空
8  type 为 undefined/""          -> 身份不能为空
9  type 不是 学生/教师            -> 身份格式只能是学生、教师
10 position 为 undefined/""      -> 角色不能为空
11 instrument 为 undefined/""    -> 使用乐器需选择
12 position 不是 正式队员/预备队员/指挥 -> 角色格式只能是正式队员、预备队员、指挥
```

**注意顺序**：`instrument` 的非空检查（第 11 条）**排在** `position` 的枚举检查（第 12 条）之前。

**任一行失败即整批中止**（`return`），不会跳到下一行。因此每个含错文件**只能观察到一条错误信息**，且是**遍历顺序中第一条被校验到的失败行**。

## 4. 三个必须知道的既有行为

### 4.1 【重大】第一行数据被静默跳过

`xlsx2json` 返回的 `sheet` **已经是去掉表头后的数据行数组**（`sheet_to_json` 默认模式把表头吃掉了），
而 `importExcel` 的两个循环仍然从 `i = 1` 开始：

```js
const sheet = res[0].sheet          // 已不含表头，sheet[0] 是第一条成员
for (let i = 1; i < sheet.length; i++) { ... }   // 从 1 开始 -> sheet[0] 永不校验
for (let i = 1; i < sheet.length; i++) { data.value.push(...) }  // sheet[0] 永不导入
```

**结果：每条 Excel 的「第一条成员」既不被校验，也不会导入。**

实测（见第 7 节回放结果）：

| 文件 | Excel 数据行 | 实际导入 | 被丢弃 |
| --- | -: | -: | --- |
| `01_normal.xlsx` | 38 | **37** | 第 1 行「钱浩然」 |
| `10_large.xlsx` | 1000 | **999** | 第 1 行 |

`PersonTable.vue:322` 的注释只写了「报错行号比 Excel 实际行号小 1」，**没有点出「首行被整行丢弃」这一后果**。

### 4.2 报错行号与 Excel 行号差 2

报出的 `第N行` 中的 N 是 `sheet` 的**数组下标**（0 基，且循环从 1 起）。

```text
界面提示「第 N 行」  ⇔  Excel 实际第 N + 2 行
```

实测：`07_boundary.xlsx` 提示「第10行年龄不能为空」，对应 **Excel 第 12 行**（`age=0` 用例）。

### 4.3 两层校验的差异

前端通过 ≠ 后端通过。以下值**前端放行、后端拒绝**：

| 值 | 前端 `exportCheck` | 后端 `store_people` | 最终结果 |
| --- | --- | --- | --- |
| `name` = `"   "`（纯空格） | 通过（JS 中非空字符串为真） | `.strip()` 后为空 → 拒绝（`services.py:142`） | 整批失败 |
| `age` = `"abc"` | 通过（非空字符串） | `IntegerField` 转换报错 | 整批失败 |
| `name` 超过 255 字符 | 通过（无长度校验） | 数据库 `varchar(255)` | 取决于数据库 |

后端**只强制 `name` + `card` 非空**、且 `card` **全局唯一**；前端要求的另外 7 项（age/gender/school/phone/instrument/type/position）后端完全不看。

## 8. 数据安全声明

- 姓名、学校、专业均为**虚构**（姓氏/名字池确定性生成）。

- 未从任何数据库导出或复制真实信息。
- `person.card` 全局唯一，测试值与正式数据天然隔离。
